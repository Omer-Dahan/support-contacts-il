# המלצת פורמט וסכמת שדות

תאריך כתיבה: 2026-08-27

## 1. השוואת פורמטים

| פורמט | יתרונות | חסרונות | מתאים ל... |
|---|---|---|---|
| **VCF (vCard)** | תקן פתוח (RFC 6350), נתמך native בכל טלפון (iOS/Android), ייבוא בלחיצה אחת, אין צורך באפליקציה | לא תומך היטב בשדות מותאמים אישית (שעות פעילות, "תאריך אימות") ללא הרחבות לא-סטנדרטיות (`X-` fields) שחלק מהטלפונים מתעלמים מהן; קשה לעדכן בהמוניות אחרי ייבוא (משתמש צריך לייבא מחדש); אין "מקור אמת" חי | **פלט סופי** לייבוא לטלפון — לא מקור הנתונים |
| **JSON** | גמיש לחלוטין, תומך בכל שדה (כולל מקורות, תאריכי אימות, קטגוריות מקוננות), קל לעבד בקוד (בוט, סקריפט ייצוא ל-VCF), נוח ל-git (diff קריא) | לא ניתן לייבוא ישיר לטלפון; דורש שכבת קוד להצגה/שימוש | **מקור האמת (source of truth)** לנתונים |
| **CSV** | פשוט, נפתח באקסל/Google Sheets, קל לעריכה ידנית ע"י מי שלא מתכנת | לא תומך במבנה מקונן (למשל מספר טלפון + סוג מספר טלפון), בעייתי עם עברית/קידוד/פסיקים בתוך שדות, אין תמיכה בהיסטוריה/הערות | טוב ל**עריכה ידנית/שיתופית** (למשל Google Sheets כממשק תחזוקה), פחות טוב כמקור אמת ארוך טווח |
| **SQLite** | שאילתות מהירות, יחסים בין טבלאות (חברה↔קטגוריה↔ערוצי קשר↔מקורות), מתאים לבוט עם הרבה שאילתות | overkill לפרויקט קטן-בינוני; לא ידידותי לעריכה ידנית או ל-diff ב-git; דורש כלי ניהול DB | אופציה **עתידית** אם המאגר יגדל משמעותית או הבוט יזדקק לחיפוש/סינון מורכב |
| **Google Contacts API** | סנכרון אוטומטי ישיר לאנשי קשר של המשתמש, עדכון בזמן אמת בלי ייבוא ידני | דורש הרשאות OAuth, תלות בחשבון גוגל, לא מתאים לכולם (מי שמשתמש ב-iCloud/Outlook), מורכבות פיתוח גבוהה יחסית לתועלת | תוסף **עתידי אופציונלי**, לא לשלב ראשון |

## 2. המלצה

**ארכיטקטורת שכבות:**

1. **מקור אמת: JSON** — קובץ (או תיקיית קבצים, אחד לכל קטגוריה) בפורמט JSON לפי הסכמה למטה. נשמר ב-git, כך שכל שינוי מתועד עם היסטוריה (מי עדכן מה ומתי — חשוב לאור הדרישה ל"תאריך אימות").
2. **ממשק תחזוקה (אופציונלי):** ניתן לייצא/לייבא ל-CSV/Google Sheets לצורך עריכה שיתופית נוחה ע"י מי שאינו מתכנת, עם סקריפט המסנכרן בחזרה ל-JSON.
3. **פלט לטלפון: VCF** — נוצר אוטומטית (סקריפט המרה) מה-JSON. כל אנשי הקשר מיוצאים לקובץ `.vcf` אחד לייבוא מלא, עם:
   - שם התצוגה: `"<חברה> - <קטגוריה>"` (למשל "בנק הפועלים - שירות לקוחות")
   - הערה (`NOTE`) הכוללת שעות פעילות + תאריך אימות + URL מקור, כדי לשמר את המידע גם בתוך הטלפון
4. **אינטגרציה עם בוט (טלגרם):** הבוט קורא ישירות מה-JSON (או ממנו נטען ל-SQLite/זיכרון בזמן ריצה לחיפוש מהיר), ומחזיר למשתמש תשובה מבוססת השאילתה (למשל "מה מספר הטלפון של בנק לאומי?").
5. **שדרוג עתידי אם נדרש:** אם מספר הרשומות יגדל משמעותית (מאות רבות) והבוט יזדקק לחיפוש טקסט חופשי/פילטרים מורכבים — להעביר את שכבת הקריאה (לא בהכרח את מקור האמת) ל-SQLite שנבנה מה-JSON בזמן build.

**סיכום:** JSON כמקור אמת → VCF כפלט לייבוא לטלפון + קריאה ישירה מה-JSON (או SQLite נגזר) לבוט.

## 3. הצעת סכמת שדות (JSON)

```json
{
  "id": "bank-hapoalim",
  "company_name": "בנק הפועלים",
  "company_name_en": "Bank Hapoalim",
  "category": "בנקים",
  "subcategory": null,
  "contact_channels": [
    {
      "type": "phone",
      "value": "*2407",
      "label": "מוקד טלפוני כללי",
      "verified": true
    },
    {
      "type": "phone",
      "value": "03-5673333",
      "label": "מספר מחוץ לישראל / קווי",
      "verified": true
    },
    {
      "type": "email",
      "value": null,
      "label": "לא פורסם באתר הרשמי",
      "verified": false
    }
  ],
  "hours": {
    "text_raw": "א'-ה' 8:00-20:00, ו' 8:00-12:00",
    "verified": true
  },
  "address": {
    "text_raw": "יהודה הלוי 50, תל אביב",
    "verified": true
  },
  "source_url": "https://www.bankhapoalim.co.il/he/contact-us",
  "verification_date": "2026-08-27",
  "verification_status": "verified",
  "notes": ""
}
```

### הערות לסכמה
- **`contact_channels` כמערך** ולא שדה בודד — כי לחברה יכולים להיות כמה מספרי טלפון/מיילים (כללי, VIP, עסקי, תלונות).
- **`verified` ברמת כל ערוץ בנפרד** — לא כל השדות של חברה מאומתים באותה רמת ודאות; מספר טלפון יכול להיות מאומת בעוד שעות הפעילות לא פורסמו.
- **`verification_status`**: `"verified"` / `"unverified"` / `"outdated"` (פג תוקף לפי מדיניות עדכון, ראו RESEARCH.md סעיף 5).
- **`source_url` חובה** לכל רשומה שמסומנת `verified` — בהתאם לדרישת "אל תמציא, סמן לא מאומת אם אין מקור".
- **שדות עתידיים אפשריים** (לא בשלב ראשון): `logo_url`, `app_store_link`, `chat_url` (צ'אט אונליין), `social_media` (עמודי פייסבוק/וואטסאפ עסקי לשירות לקוחות — נפוץ מאוד בישראל).

## 4. מיפוי שדות ל-VCF (vCard 3.0/4.0)

| שדה JSON | שדה VCF |
|---|---|
| `company_name` | `FN`, `ORG` |
| `contact_channels[type=phone]` | `TEL;TYPE=WORK,VOICE` (אחד לכל ערוץ) |
| `contact_channels[type=email]` | `EMAIL;TYPE=WORK` |
| `address.text_raw` | `ADR;TYPE=WORK` |
| `category` | `CATEGORIES` |
| `hours` + `verification_date` + `source_url` | מקובצים לתוך `NOTE` (אין שדה ייעודי בתקן) |
